# METIS 统一插件入口

## 1.6.0：自由研究网络

研究项目的六个（或自定义数量的）阶段是网络骨架。目标、冻结步骤提示词的短摘要、交付要求、禁止事项、达标规则、技能绑定与输出格式形成配置节点；实际执行产生的调用、读取对象、结果回执、核验与交付物形成记录节点。实体按空间分簇自由排布，不再受三列步骤卡布局限制。

配置与执行记录分开标明。网络节点数量不当作研究步骤或已完成任务数量；没有实际调用时不会生成调用/成果记录。实际活动沿用最近 96 条持久回执，不生成虚构 Agent 或模型思维。新节点随真实记录出现，执行中的链路点亮；全景、镜头跟随、缩略导航、完整网络/执行记录筛选均可用。

点击实体可查看真实内容、状态和退出码，并关联所属阶段的原生助手；交付文件直接进入已有原地编辑层。旧项目固定配置保持，新界面只读取其冻结配置的少量摘要，不重编旧流程或把技能正文全部加载到上下文。模式编排保留原编辑方式。

新增客户端源 `research-network.js`、`ion-research-network.js`，仍随完整 `display-client` 单模块离线发布。隔离验证与边界见 Codex 工作目录 `work/METIS_RESEARCH_NETWORK_20261107.md`。本轮没有刷新、重启或操作用户当前窗口。

## 1.5.0：离子回路主界面

METIS 默认打开最近的研究项目；没有项目时进入模式画布。回路是实际操作空间：点节点编辑或查看本步，拖动模式节点调整真实顺序，拖入具体技能形成步骤绑定，循环端口对应本步真实达标条件。顺序执行与达标循环沿用现有引擎，未声明任意分支或并行流程。

右侧常驻原生 DSH 对话，可拖动调整宽度。模式画布与 AI 共用同一草稿，保留人工字段保护，最后一次“保存并生效”。项目画布使用其原有冻结版本；查看节点只改变助手的消息上下文，不会冒充执行或改写进度。

已登记的真实交付物作为节点附件端口，点击在画布内预览和编辑，返回保留原会话草稿。未保存文档阻止上下文切换。开始、停止按钮调用原生会话控制；未发送草稿时禁用开始，固定版本不符时拒绝，重复开始请求持久去重。技能正文与资源继续渐进读取，依赖不因浏览界面自动安装。

三维画布和界面仍通过已有 `display-client` 单一离线模块加载，保留旧 `createResearchScene` 入口，不依赖二级渲染 URL；图形不可用时保留实际节点和原生对话的备用入口。本轮没有自动热更新、刷新或重启用户 DSH。独立验证与边界见 Codex 工作目录 `work/METIS_CIRCUIT_CORE_20261107.md`。

统一包1.2.0已于2026-11-05在用户确认退出DSH后应用到desktop：三项直接依赖/选择及本地链接合并为一个METIS。8项真实安装导出可解析，两个锁文件仅修改METIS入口，模式和旧会话索引哈希保持不变。此前已用真实桌面DSH 0.2.1-rc.5隔离验证完整模块、原生启停、MCP、前端与旧会话恢复；迁移后未启动用户桌面，现场显示由用户打开后确认。

用户安装、启停、升级的对象只有 **METIS**。技术包名继续使用 `metis-academic-preset`，保留旧会话中记录的 `metis-academic-preset/step-skills` 导出；内部目录与包名不再作为独立安装入口。

## 包的边界

统一清单位于项目根 `../../package.json`。之所以把发布根放在整个项目根，而不是复制进一个新插件目录，是为了同时保留：

- 现有 `dsh-plugin/metis-academic`、`metis-mode`、`metis-preset` 的相对路径，仍编辑原文件。
- 完整`src/metis_academic` Python引擎、workflow与技能资源，以及对应`pyproject.toml`，避免仅打包技能正文却遗漏实际引擎。
- 现有 `metis-preset/library` 的固定来源与历史资源，不复制一份接近 1 GB 的资料。

`files`明确只包含METIS模块、Python引擎/资源和本统一入口；包内`.npmignore`排除测试与pycache，`designcraft`、`ares`、测试、研究项目、账号和会话数据不在该白名单内。包管理器自身可能附带的根 README 等标准说明文件遵循其原生打包规则。本包私有且没有发布操作。

入口使用 `.mjs`，项目根没有新增 `type: module` 设置，以免改变其他目录中 JavaScript 的解释方式。

## 内部加载与统一开关

| 稳定行 ID | 单包导出或原生模块 | 职责 |
|---|---|---|
| `metis-academic` | `metis-academic-preset/runtime` | 注册 METIS 运行时技能 |
| `metis-mcp` | `@deepseek-ai/dsh-mcp-client` | 连接既有 Python 引擎 |
| `metis-academic-mode` | `metis-academic-preset/workbench` | 工作台路由、配置助手、模式状态 |
| `preset-metis` | `metis-academic-preset` | 模式、步骤、渐进技能与旧会话版本保护 |

全部行由一个`cordis.patch.yml`所有，交给DSH原生bundle开关与生命周期处理。runtime提供实际Python源路径，MCP通过显式PYTHONPATH读取随包引擎，不靠旧全局editable安装指向。根入口位于三个旧包作用域外，DSH 从统一清单发现唯一的浏览器声明；`runtime`、`workbench` 子路径不再各自声明一份浏览器模块。主题、面板、进度条仍走原有清理逻辑。

左侧插件管理里的 METIS 总开关控制包加载；工作台内部的 METIS 模式开关继续决定研究模式是否显示。这两个现有层级保持各自含义。原 profile 中用户设置的逐行禁用仍保留，不擅自清除。

## 构建插件

在根目录安装开发依赖后，修改宿主或父客户端代码时运行：

```powershell
npm run build
```

`prepare-host.mjs` 将五个服务端入口的实现一起构建到带内容摘要的 ESM 文件。桌面宿主通过固定入口检测更新，研究会话按各自版本加载步骤工具。`host-build.json` 记录源码摘要、产物路径和 Node 内置依赖。DSH 直接使用已生成的文件。

`prepare-ion.mjs` 将 MIT Three.js 与离子回路界面离线打包，记录渲染器和界面源码摘要；开发依赖固定为 Three.js 0.187.0 与 esbuild 0.28.2。运行插件无需下载这些开发依赖。`prepare-client.py` 从 `../metis-mode/client/client.js` 生成本目录的 `client.js` 并记录源码摘要。`prepack` 执行相同的构建。步骤编辑器 `composer.js` 继续按宿主返回的 `editorRevision` 读取。

## ION 科研指挥舱（1.4.0）

METIS 的模式编排、技能库、研究项目与文档审阅共用一套黑紫、橙金和暖白的界面。宽屏顶栏只有一行：METIS 开关、编排/研究导航、当前模式或项目及相关主操作。较窄的嵌入窗口会调整顶栏排列；原有三栏拖拽、快捷键和对话草稿保持。

- **模式编排**：流程节点与连线、头部直接编辑步骤名称、紧凑的目的/交付/技能/提示词/禁止事项面板。AI 更新依据实际共享草稿差异高亮，三向合并继续保留手改字段；一次保存并生效仍只影响新会话。
- **技能库**：真实子技能卡片、来源筛选与分页、正文和资源详情抽屉。选择具体技能才按片段读取，保持渐进披露；创建/安装/修改继续由原生配置助手和已有工具完成。统计来自实际目录，来源数与技能数不代表依赖或科研效果已验证。
- **研究控制台**：可折叠项目列表、离子现场/实际交付物切换、横向选步与单步详情。看哪一步与执行哪一步保持独立，右侧原生助手按发送时的查看范围处理意见。
- **文档审阅**：真实格式标记、预览/编辑、段落/单元格或文本选择关注位置、把当前内容带入原生研究草稿。保存继续核对文件版本，手动修改后待研究助手核验。未保存时阻止 METIS 内的跨页或项目切换，保存成功或明确放弃后再解除提醒。

点击反馈、节点切换、抽屉、字段更新和保存反馈均有短动效；系统减少动态时关闭这些过渡。镜头与离子仍只依据真实执行状态变化，普通编辑不会制造研究进度。键盘切页和抽屉关闭保留正确焦点。

设计源为 `../metis-mode/client/ion-workbench.css`。构建先执行 `prepare-ui.py`，把同一份 CSS 嵌入父客户端和独立编排/文档模块，并生成 Scene 的静态样式模块；然后执行完整场景、宿主和统一客户端构建。浏览器不需要额外的主题资源接口或相对动态模块。`ion-ui-build.json` 与 `ion-build.json` 记录实际源码和产物摘要。

嵌入对话的模型选择、工具、流式消息、停止、队列和历史继续由 DSH 原生组件处理。文档编辑范围沿用下面 1.2.4 节的能力边界；完整论文或具体技能的科研有效性不由界面验证代替。需要完整前端加载时，请在方便时正常重开 DSH；本版不自动操作窗口或调用全局插件更新。

## 研究执行动态（1.2.3）

项目顶部与各步骤显示真实工具调用的开始、结果、时长及失败/停止状态，点击可展开调用详情。浏览某一步与当前执行步骤分别记录，浏览不会推进流程。右侧继续使用 DSH 原生研究对话。

记录按项目原会话及固定流程版本保存，最多保留最近 96 次调用，返回摘要最多 1200 字符；不预载所有技能、不生成虚拟进度或模型内在推理。后台命令按实际任务回执和退出码判断状态；跨进程旧执行显示中断，旧后台任务显示待确认。此版需要运行时和客户端一同加载，已有进程保留旧步骤插件时请正常重开 DSH。

## 交付物预览与编辑（1.2.4）

在研究项目中点击某一步交付的文件名，直接在中间栏预览或编辑，右侧仍是该项目原生研究助手。支持 DOCX/PPTX/PDF/XLSX 的实际页面预览、Markdown 渲染及 TXT 阅读；编辑支持 Word/PPT 段落与表格文字、Excel 单元格与公式、PDF 原位置文字替换、MD/TXT 正文。可用「交给研究助手」把文件及关注位置插入原草稿，不自动发送。

「保存文档」直接保存回项目原文件，检查打开时的 SHA-256，拒绝覆盖并发修改。原交付留在历史，手动修改后的步骤标为待核验，后续步骤不自动重做。跨重开保持原项目会话和固定流程配置。

Word/PPT 复用 MIT 文档审阅台的按 run 差分实现，页面转换复用 DSH 原生 Office 服务，其余文件操作使用本地 Python 库；上游原许可和固定来源位于 `../metis-mode/host/document-vendor/`。没有增加独立插件、付费 SDK、外部文档上传或全局 Office 技能替换。

直接编辑是有范围的：Word/PPT 以文字修改为主；PDF 不自动重排整页，超出原位置会拒绝保存，扫描件只提供页面预览；Excel 直接编辑限每表 250 行、50 列、12 张表和总计 12000 个可见单元格，大表仍可预览并交给研究助手按范围处理。Markdown 图片显示替代文字。旧 DOC/PPT/XLS 提供原生预览入口，需转成 OOXML 才可直接编辑。文档编辑需要本机现有 `python-docx`、`python-pptx`、`openpyxl` 和 `PyMuPDF`，实际缺少时会说明，启动 METIS 本身不依赖这些库。

## 离子回路（1.3.1）

研究项目标题下的「研究现场」采用 ION 离子回路，替换旧星环。深色电路墙、橙金走线、立体步骤卡与离子光球组成一个可旋转、缩放的场景；全景、跟随、放大与收起均可直接操作。卡片数量和名称来自本项目固定的模式步骤，点卡片同步右侧原生研究助手的查看范围，查看详情才滚动到步骤正文。

采用独立编写的 Three.js/WebGL2 与 CSS3D 实现，参考 [Agent Display](https://github.com/cyberdaddyleo/agent-display) 的 ION 视觉思路。参考仓库单独存放，不打包其代码、模型、素材或模拟器。Three.js MIT 原许可和固定来源在 `../metis-mode/client/ion-vendor/`。没有随机任务、虚构多 Agent、伪造成本和评分；装饰电路不代表业务事件。交付、待核验、失败和停止来自真实会话记录，真实工具执行才使对应步骤出现离子流光，浏览和普通讨论不冒充执行。

1.3.1 将界面与三维引擎一起离线构建成现有 `display-client` 单一模块，用同一个内容摘要加载。不再依赖父客户端传入 `displayRendererRevision` 或另一个动态渲染器地址，兼容旧宿主/旧父客户端与新资源的组合，修复 `dsh-app://app/.../display-renderer?v=undefined` 加载失败。独立渲染器接口暂保留给已缓存的旧界面，新界面不请求它。构建会拒绝残留的外部模块导入。

场景按需加载，不增加模型请求或研究提示词。空闲不持续绘制；收起或离开可见区域时暂停，收起释放图形资源与 WebGL 上下文。减少动态时静态表达调用状态，WebGL2 不可用时保留真实步骤按钮和原生对话，并显示实际图形错误。文档打开时场景释放图形资源，右侧原对话与草稿保留。旧项目继续使用各自固定配置，不通过可视化修改工作流或自动推进任务。

## 宿主升级与编排服务恢复（1.3.0）

DSH 0.2.2 将 `list_agents` 合并到原生子任务控制模块，并调整了工具执行器、会话读取和输入提交接口。旧固定工具入口会在注册时失败，原先连配置目录也无法提供。现改为先提供配置服务，再在宿主加载完成后激活真实工具；临时失败持续恢复，状态和具体错误如实返回。新模式与编排助手取当前 DSH 原生 standard 工具组成，保持原生权限、审批、沙箱和工具展示链路。

旧研究会话仍读取原固定模式、步骤、技能和提示词。仅在内存中适配宿主原生工具 ABI，不改原快照字节；新会话保存当前工具组成。项目原生输入同时兼容旧 `mintAttempt` 和新 `beginAttempt`，按发送时所查看步骤绑定请求，继续使用 DSH 的附件、草稿、队列和接受回调。

## 迁移当前三个本地链接

当前已知 desktop profile 原来直接安装、选中三个 METIS 包。**只安装第四个入口而保留原来三个，会重复加载，不能这样使用。**

迁移工具默认`Plan`只读，当前已真实执行并核对将3项METIS合为1项，其他插件保留。实际Apply要求DSH完全退出；在PowerShell 7中执行：

```powershell
# 仅查看将合并的安装项；不写配置、不调用 pnpm。
& 'D:\METIS超级合并\dsh-plugin\metis-unified\migrate-profile.ps1' -Action Plan

# 退出DSH后才可应用；2026-11-05已实际应用desktop迁移。
& 'D:\METIS超级合并\dsh-plugin\metis-unified\migrate-profile.ps1' -Action Apply
```

默认目标为 `$DSH_HOME/profiles/desktop`；没有 DSH_HOME 时为用户目录 `.dsh/profiles/desktop`，也可传绝对 `-ProfilePath`。

应用过程：

1. 拒绝桌面DSH及目标profile的相关进程；原生CLI明确使用其他profile时不阻塞、不终止。未知调用保守阻塞，整个迁移期间需保持目标DSH关闭。
2. 保留其他依赖和 bundle 顺序，用一个 `link:D:/METIS超级合并` 替换原来三个直接依赖/选择项，统一包在首次 METIS 出现的位置。三个原开关若不一致，要求显式 `-State On` 或 `Off`，不猜测用户选择。
3. 将 package、两份lock、workspace、profile patch原文及三个旧Junction目标记录备份到profile内 `.metis-unified-backups/<时间-随机标识>`。只改两个旧模块的 `name:` 字面量，保留行 ID、参数和逐行禁用。Home 层旧模块覆盖需单独审阅，工具不会修改全局层以免影响其他 profile。
4. 统一根包无npm依赖，仅精确替换两份既有锁文件的METIS本地link条目，移除两个旧Junction并将保留入口指向统一根包。不全量解析/安装其他依赖，不运行依赖脚本；校验原目标和文件哈希，失败恢复本次记录的原文件与Junction。原有其他插件锁不一致保持原样，不降级或改版本。
5. 不启动、不重载 DSH，不碰模式配置、技能资源包、会话快照、研究资料或凭据。再次由用户启动 DSH 后，才可实际确认单项显示与启停效果。

后续回退仍需 DSH 退出，把应用输出中实际的备份目录传入：

```powershell
& 'D:\METIS超级合并\dsh-plugin\metis-unified\migrate-profile.ps1' -Action Restore -BackupPath '<应用时实际输出的绝对备份目录>'
```

Restore核对备份与当前文件哈希，拒绝覆盖迁移后的新文件改动；本地链接事务恢复记录的原文件及Junction，不全量整理其他依赖。当前desktop的Apply已完成，Restore未执行。旧版无Junction记录的备份仍保留原pnpm恢复路径，可能受其原有依赖锁问题影响；应使用本次成功应用的备份记录。

## 项目内研究对话与单步返修（2026-11-05）

研究项目右侧常驻同一项目原生DSH会话，可以直接输入消息；沿用DSH模型、权限、流式消息、工具卡片、停止与历史，不另做简化聊天。空会话显示研究入口，不再要求选择工作区。切换项目按各自sessionId保留草稿，不共享会话或新开会话替代。

展开一个步骤，研究助手标题下会显示正在查看的步骤。直接输入修改意见即可。每条消息在发送时绑定项目、固定版本和步骤，随后切换步骤也能继续处理原意见。收起步骤可回到整个项目的讨论。点击“修改这一步”会聚焦对话输入框。

助手先归档并修改当前步骤，沿用它的技能、提示词和验收要求。交付后，如果还有后续步骤，对话中会出现选择。

- “保留后续结果”保留已有交付。
- “重做后续步骤”从下一步开始重做，采用刚交付的修订结果。

后续尚未开始时可选“暂不继续”或“继续后续步骤”。最后一步交付即完成。若仍不满意当前步骤，可以直接继续提意见，后续选择以最新一次交付为准。重开项目会恢复待选择状态。

返修前保存已登记交付记录与当前可读文件的真实字节，步骤内“历史交付”可查看及下载。文件早已缺失/已变化/为链接时如实记录，不能凭空恢复原提交版本。目录保留真实副本与路径，不复制链接目标。每次归档最多4096文件/512MiB、单文件128MiB；超过边界则返修不启动、不重置步骤。历史独立存于DSH_HOME/metis-project-revisions，固定模式/技能/提示词快照及旧会话配置不被返修改写。

本轮独立真实验证：6项模型/范围/历史/重建、8项后台浏览器交互、5项真实文件归档边界、2项真实循环控制边界、2项真实模型验收要求，及原18项对应回归通过。新宿主与预设功能均需加载，界面检查projectApiRevision与能力位，半更新时禁用返修并说明。未控制、刷新、热重载或重启用户现用DSH；需要用户自行正常重开加载本轮宿主代码。
