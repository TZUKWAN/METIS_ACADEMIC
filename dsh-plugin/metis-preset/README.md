## 分步配置与可变流程

`profiles.js` 提供每个模式各自的默认流程与保存模型；步骤数可以不同，不与S1–S10一一绑定。编排器支持新增、删除、复制和移动步骤。一个步骤可以关联多个引擎阶段，也可以作为自由步骤按配置顺序执行。已有项目的引擎任务不会随界面增删而被删除或伪报完成。

`step-skills.js` 在所选模式自己的作用域注册当前配置中的步骤。短总控只包含步骤路由；模型通过现有skill工具加载当前步控制器，再经`metis_library`逐项检索/分段读取实际绑定技能。移动步骤不改变其稳定ID，复制会创建新ID，删除只影响新保存的模式版本，已开始会话仍保留原组成。

可变步骤的实际编辑、增删、复制、拖动、键盘排序、保存和人工字段保留已在独立后台浏览器验证，不接管用户正在使用的桌面。

## 配置仓库与技能资源

`configuration.js`管理版本化工作区；`workspace-edits.js`处理模式、技能和跨模式步骤操作；`skill-packages.js`读取技能来源并生成内容寻址包。工作区保存在`<DSH_HOME|~/.dsh>/metis-composer-configuration.json`，技能包位于同级`metis-composer-packages/<sha256>/files/`。旧`metis-mode-profiles.json`只作兼容读取，只有用户保存才写新仓库，旧文件保留。

创建和修改技能支持真实正文、说明、调用策略及附属UTF-8文本文件；安装支持用户明确提供的本地技能根目录和公开GitHub仓库。兼容常见SKILL.md标量frontmatter或METIS的SKILL.yaml+INSTRUCTIONS.md；不支持的复杂标量明确报错，不执行安装脚本或自动装运行依赖。GitHub固定实际commit并核对每个下载文件的Git blob哈希。

每包最多128个文件、单文件4MiB、合计20MiB，配置正文8MiB。拒绝路径越界、文件/目录冲突、大小写冲突、符号链接、子模块和凭据文件；依赖目录与缓存目录跳过并记录。二进制资源保留随包导入，当前直接编辑仅针对文本资源。包暂存不等于已保存安装。

新定义带`disclosure: progressive-v1`：不把全库或模式全部绑定技能注册成模型可见摘要，只公开步骤控制器和一个`metis_library`工具。显式开放手动调用的用户技能仍可保留user-only入口。旧会话没有该标记时继续使用原`metis-library-*`和原frozenSteps。技能正文及固定资源仍进入会话版本，删除被引用技能需先解绑或明确解除绑定，旧包不自动清理。

## 科研技能库与渐进披露

2026-11-01按刘总给定10仓库及其第一层显式集合/子模块引用构建真实数据：`library/index.json`指向内容哈希目录，`catalogs/`存元数据，`records/`与`bundles/`保留固定commit的正文、资源和许可来源。当前构建记录2194个入口、26个来源；其中8个仅有YAML清单、1个frontmatter无效，标成只读而不伪造可调用技能。完全重复正文有duplicateOf，原来源均保留；这不是2194项已在METIS运行通过。

`skill-library.js`提供有限候选搜索和单项物化。索引是虚拟库，不把几千正文写入工作区JSON；`configurationSkills`只合并元数据。只有读取/绑定一个具体条目才处理其正文/资源。普通自建/导入包仍按原20MiB/128k正文限制，固定来源库包支持64MiB与2MiB正文；ZIP按4MiB分块，继续遵守会话资源512文件/64MiB限制。

每技能资源范围为其目录、可解析的相对引用闭包及祖先许可文件，其他嵌套技能独立检索。大于2MiB的资源和稀疏来源未下载的资源按原Git blob SHA延迟读取；只请求记录的commit，校验失败或上游不可取时失败，不追HEAD。未带新执行标记的旧会话中，`prepare`仅在拥有的版本化缓存中准备真实来源文件，不执行脚本、不安装Python/R/MCP/浏览器环境，也不表示这些环境已经可用。不能解析的外部依赖和不兼容Windows路径仍需适配。

运行流程：先加载一个步骤控制器 → `open`该步 → `list`检索本步绑定（默认8项）→ `read`一个技能片段（默认4000、最多6000字符）→ 需要时`files`分页和`resource`单文件片段。工具按真实Agent隔离当前步骤，不能直接读另一未进入步骤或未绑定技能。`prepare`只是文件准备，不是研究执行。旧会话固定的正文/ZIP清单与资源版本继续保留；延迟资源需要缓存或网络，缺失时不换最新版。

编排助手现在使用DSH原生会话与真正工具，没有私有模型调用次数、累计读取轮次或合计披露预算。先通过`metis_config_read`检索少量候选，单项正文/资源继续按片段和nextOffset渐进读取。活跃步骤先披露12个绑定ID并标记截断；`bind_skill`/`unbind_skill`逐项保留其余绑定。搜索仍按真实元数据与来源评估声明辅助排序；上游自报和METIS未实测状态分开保留。

修改长正文可提交读取响应的bodyHash与唯一find/replace片段，后端核对完整正文哈希和唯一匹配后局部替换，其他文字保留；不用把未读取的长文整体覆盖成短片段。全文修改与局部替换不可混用，最多20项、每片段8000字。

重新构建仅运行我们自己的数据程序（不运行上游脚本）：`python scripts/build-library.py --cache <已获取的固定来源缓存> --output <本包library目录>`，构建需要PyYAML。构建与来源哈希核对不是插件测试；当前已另外验证真实DSH加载、模型选配、资源/依赖准备与调用链，完整外部服务和科研质量仍按实际使用验证。

正式保存先校验全部配置，更新受影响的原生定义后写入版本化文件；失败尝试恢复旧定义并如实报告恢复异常。文件版本冲突不会覆盖现有保存值。保存后的通知失败与提交失败分开报告，避免已写入新文件后错误地回滚到旧定义。

## 会话固定版本与跨重启恢复

`session-versions.js`把真实插件声明、Persona前缀、已经编译的逐步指令、技能正文及资源副本保存为不可变哈希快照。目录是`<DSH_HOME|~/.dsh>/metis-session-versions/`：`snapshots/<sha256>.json`保存声明，`resources/<sha256>/files/`保存资源，`index.json`保存索引，`sessions.json`保存旧会话保护绑定。保留JSON配置键顺序和资源内容，不在恢复时拿最新配置重新编译。

新会话通过原生header或`agent-preset/selected`记录可读固定版本ID。配置保存只推进新会话入口，旧定义与引用资源不自动清理。恢复时只接受该ID/绑定指向的版本；快照或资源缺失、损坏、身份不一致时明确失败，不回退最新版。模式开关只影响新建目录和默认选择，不阻止已记录历史ID恢复。

`session-routing.js`适配原生创建/恢复、空白会话复用和冷技能目录；使用原始方法descriptor保留Cordis调用者所有权，卸载时恢复包装。对已有运行中旧METIS Agent，读取实际PresetTree及已注册步骤正文建立快照，不重绑其正在运行的作用域。存在无法确认的分组/动态声明或资源时拒绝猜测，保存新配置前必须完成保护。

升级前从未记录版本、也无法读取原运行组成的cold旧会话，不能凭空还原丢失历史。默认拦截自动恢复，工作台“会话版本”可查看真实声明后显式选择保护基线；基线不会标成原始历史，已固定或损坏的绑定不能借此换成新版。原生日志是固定ID时优先依日志恢复，审计索引不是把旧会话重映射到最新的依据。

冻结范围是METIS配置和声明的技能资源；DSH/插件程序实现、帐号凭据、当前时钟和研究文件不冻结，模型选择历史沿用DSH原生机制。资源快照限制512文件、单文件16MiB、合计64MiB，声明32MiB。不可完整保存时不截断伪装成功。当前已有独立原生Host重建、恢复、并发和UI验收；未未经许可重启用户现用DSH。

此前曾验收过初始十个定义、九个原生菜单选择和开关显隐；这些结果不证明后续新增功能已可运行。本轮实际下载固定来源并构建库数据，插件改动只做源码人工阅读；没有语法检查、插件测试、实际依赖安装、DSH/模型API调用、截图或主动加载。


## 原生配置助手

`composer-definition.js` 提供隐藏的 `metis.composer` 纯声明，`composer-agent.js` 只实现真正的 `metis_config_read` / `metis_config_edit` 工具，由DSH共享Agent loop执行。Host不再静态导入动态工具插件。编排组成直接读取当前注册的DSH `standard` 声明及其解析Context，保留实际平台条件、用户配置、工具分组和展示模式，只替换persona并加入两项配置工具；不再复制本地工具清单或强制native模式。全部宿主已启用全局工具/MCP按DSH自身作用域和权限继承，没有METIS额外白名单、自建LLM流、三次循环或私有历史截断。`base-plugins.json`只继续服务原研究版本声明，不再作为编排助手的工具来源。

`composer-operations.js` 把操作规范拆成按需读取条目；工具能力覆盖现有真实配置操作。`composer-workspaces.js` 管理AI与人工共同草稿、hash/revision冲突合并和真实Session绑定。工具直接更新同一待保存流程，人工显式编辑的字段优先；用户最后一次保存并生效仍经过原有会话固定版本保护，不另设应用提案步骤。

同一编排会话派出的真实DSH子Agent/队友通过原生 `agents.get/list/isOwnedBy` 的活体所有权链定位该会话草稿，共用revision和串行提案锁，不要求队友再选目录或建立独立配置绑定。其他根会话、伪造Agent、仅在历史日志声明parent的独立会话均不能借此访问。安装来源授权只读取绑定根会话的真实用户消息与以前保存的来源，不把队友消息当刘总授权。文件/终端工具可读取编排所需的真实材料，配置写入仍走提案与保存流程。

接入协议v4保持兼容，能力修订9在open/bind时通过DSH `sessionController.resolveAgent`恢复既有真实Agent，不只打开历史记录；不创建替代会话、不注入用户消息。状态及模型前守卫比较主编排Agent的完整工具目录与真实standard generation，检查标准工具、METIS工具、wire schemas和展示模式。原生子Agent仍遵守DSH自身的委派工具过滤，不强迫受限子Agent取得根会话全部工具。权限从原生permissionPresets/sandboxPolicy/approval服务读取；保留本会话选择，提供DSH相同选项，不强制更改为完整访问。真实观察写入原编排记录的runtimeObservation，供本机审计，未激活记录不冒报ready。

可选配置`composerBasePreset: standard`声明实际基准；`composerResumeWorkspaceId`用于一次恢复指定既有编排，成功标记保留，普通重连不会清掉。配置经DSH原生profile HMR应用，不依赖模拟按钮请求，不擅自重启。METIS Host现在复用Connection认证并将全局配置限定所有者，避免建立未认证的Agent恢复入口。旧研究快照/路由与人工草稿不改，原生工具调用与实际模型执行已在隔离环境通过验证。

## 子技能绑定与原生按需执行

编排助手通过 `metis_config_read` 分页检索并读取实际子技能正文，再用 `metis_config_edit` 绑定到步骤；新引入的库技能须有对应来源版本的正文读取凭据，不能仅凭仓库名或搜索结果绑定。用户点击一次“保存并生效”提交，研究开始前不批量安装所有依赖。

`execution: native-on-demand-v1` 和新版 `native-goal-loop-v1` 都支持原生按需执行，后者另含可选目标循环。`metis_library` 先 `open` 当前步骤，再 `load/read` 所需子技能首段，之后才允许 `prepare/call/run`。`prepare` 按需准备真实资源、隔离 Python/Node 包及所需模块/CLI，环境按固定模式、工作流和技能版本区分；`call` 派发当前 Agent 实际可见的 DSH 工具用于 MCP、其他运行时和依赖准备；`run` 在已准备环境中执行真实命令。派发经过 `tools.execute` 的完整原生权限、沙箱、取消和结果链，实际子调用写入原生程序调用记录。

安装只有真实退出码、模块/CLI 检查和对应尝试回执齐备才返回就绪；后台任务继续等待原 job，不重复启动。失败、缺解释器/MCP、权限、凭据等原样返回，不能把导出文件、加载正文或安装成功当成科研成果。旧声明没有新执行标记时保持原资源导出约定，既有会话的固定配置不改写。

AI和界面共用editor.configuration，AI编辑不再产生另一份等待应用的提案。前端按稳定步骤ID进行三方合并，保留尚未送达的手改；本轮显式手改字段有保护，冲突时保留人工值并反馈AI。模式创建/改名/删除只修改同一待保存流程，最后一次保存并生效才通过原配置CAS和会话保护发布。旧提案迁移而不丢编辑内容；草稿条目不提前进入研究模式选择器。

聊天中只显示紧凑进度条，不点击跳入工作台。`runtimeProgress`读取该会话固定版本的步骤和实际执行记录，不读取最新模式替代；自由工作流不必先创建研究项目。循环核验中/待修订/等待处理不会被表示为全部交付；原有项目型会话保留旧进度来源。

## 项目内研究对话与单步返修（2026-11-05）

研究项目右侧常驻同一项目原生DSH会话，可以直接输入消息；沿用DSH模型、权限、流式消息、工具卡片、停止与历史，不另做简化聊天。空会话显示研究入口，不再要求选择工作区。切换项目按各自sessionId保留草稿，不共享会话或新开会话替代。

展开一个步骤，研究助手标题下会显示正在查看的步骤。直接输入修改意见即可。每条消息在发送时绑定项目、固定版本和步骤，随后切换步骤也能继续处理原意见。收起步骤可回到整个项目的讨论。点击“修改这一步”会聚焦对话输入框。

助手先归档并修改当前步骤，沿用它的技能、提示词和验收要求。交付后，如果还有后续步骤，对话中会出现选择。

- “保留后续结果”保留已有交付。
- “重做后续步骤”从下一步开始重做，采用刚交付的修订结果。

后续尚未开始时可选“暂不继续”或“继续后续步骤”。最后一步交付即完成。若仍不满意当前步骤，可以直接继续提意见，后续选择以最新一次交付为准。重开项目会恢复待选择状态。

返修前保存已登记交付记录与当前可读文件的真实字节，步骤内“历史交付”可查看及下载。文件早已缺失/已变化/为链接时如实记录，不能凭空恢复原提交版本。目录保留真实副本与路径，不复制链接目标。每次归档最多4096文件/512MiB、单文件128MiB；超过边界则返修不启动、不重置步骤。历史独立存于DSH_HOME/metis-project-revisions，固定模式/技能/提示词快照及旧会话配置不被返修改写。
