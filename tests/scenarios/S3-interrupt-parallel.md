# S3 — 中断恢复 + 并行执行验收场景

## 目标

验证：(a) 执行中强制终止子智能体后，重派新子智能体不丢进度（任务级锁可恢复、
状态不损坏）；(b) 两个无依赖任务可并行执行且互不干扰。

## 前置条件

同 S2（journal × qualitative 项目，工作目录 `D:\METIS超级合并`）。

## 用户输入序列

1. 「执行 C-S1-001」（第一个子智能体开始后立即强制终止其进程——模拟方法：
   子智能体 A 只做"抢锁后挂起"（用 python 启动一个占锁子进程再杀掉它，
   或由执行者直接 kill 该子进程），模拟执行中崩溃）
2. 「子智能体崩溃了，重派一个继续」
3. 「C-S1-001 和 C-S1-002 并行执行」

## 验收清单

| # | 断言 | 判定方式 |
|---|---|---|
| C1 | 崩溃模拟后 `.metis/locks/C-S1-001.lock` 存在且含死 PID | 读锁文件 |
| C2 | 新子智能体 `exec C-S1-001` 成功接管 stale 锁并完成任务（退出码 0） | 命令 |
| C3 | 状态零丢失：接管后 project/workflow/task-state 均可正常读取，C-S1-001 = COMPLETE | 读文件 |
| C4 | 并行：两个无依赖任务（C-S1-001 ready 后与 C-S1-002——注意 journal S1 的 C-S1-002 依赖 C-S1-001，改用两个 different-stage 无依赖任务或重置场景；执行者可用 C-S2-001 与 C-S1-001 并行）同时 exec 均退出码 0，互不覆盖产物 | 命令 + 产物 |
| C5 | 并行期间锁互斥：同任务双开必有一方 TaskLockError | 集成测试输出 |
| C6 | 任务级进度零丢失：全部执行后 status --json 的任务状态与实际产物一致 | status 输出 + 文件 |

## 判定标准

C1–C6 全成立 → S3 = PASS；否则 FAIL + 证据。
