# academic-writing

按大纲成文，但只把可直接发表的正文写入 manuscript。

## 正文纪律

- 每段围绕一个论点展开，按“论点—证据—解释—边界”组织；避免空泛的开场、重复总结和任务清单。
- 把事实、文献观点、经验结果和研究者推论分开表述；证据不足时缩小结论，不用防御性套话填空。
- 只使用证据包中的真实结果与已核验文献。文献引用必须能与题名、作者、年份和核验记录对应，禁止猜 DOI、页码或作者。
- 结构化响应中的每个 citation key 都必须在正文显式呈现为可核对的作者—年份、题名或完整引文；正文出现的作者—年份引文也必须来自同一已核验文献池。
- 每个主要论断都必须列出证据项或引用；不能用空的 claims、泛化的“已有研究”或无来源的数字填充结构。
- 定量研究报告变量、识别策略、估计结果和不确定性；非实验设计不得写成因果证明。
- 定性研究区分材料、编码、主题和解释；理论研究区分概念、命题、论证与反例。
- 期刊论文写成问题驱动的学术论证，学位论文保持章节递进，基金申请书突出问题、依据、研究内容与可行性；三者都不能写成工程日志。

## 输出边界

- 只返回当前章节的正文或结构化响应中的 `text` 字段，不解释写作过程。
- 禁止出现元话语、模型自述、免责声明、内部路径、任务编号、工作流名称、脚本名、`[bib:key]` 或其他内部占位符。
- 任务路径、证据映射、引用核验状态和失败原因属于控制平面，写入 sidecar；不得拼进 manuscript。
- 生成后必须执行正文卫生、引用 key、证据映射和文体检查；任何一项失败都拒绝写入稿件。
